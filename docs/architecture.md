# Architecture reference

Moved out of CLAUDE.md. Auth, email, app structure and UI patterns.

### Authentication
NextAuth.js v4 with Credentials provider. Users authenticate against Neon PostgreSQL via Prisma; passwords hashed with bcryptjs. Roles are attached to JWT tokens and exposed via session. `src/lib/auth.ts` is the central config; `src/types/next-auth.ts` extends session types; `src/types/rbac.ts` defines roles and permissions.

Password reset tokens are stored in the `PasswordReset` table in PostgreSQL and expire after 1 hour. See `src/lib/password-reset.ts`.

`verifyPasswordById(userId, password)` (`src/lib/user-database.ts`) confirms a logged-in user's own password against their `passwordHash`; used by `POST /api/customer/assignments/[id]/complete` (P8) to require password re-entry immediately before signing — a guard against an unlocked/shared device — via a `currentPassword` field on the complete page (`src/app/customer/documents/[assignmentId]/complete/page.tsx`), 400 with `passwordError: true` when missing or wrong. Not required on the public kiosk route, since no-email workers have no password.

### Email
Transactional email is sent via **Azure Communication Services (Email)** (`@azure/communication-email`). An Azure-managed sending domain (`DoNotReply@<uuid>.azurecomm.net`) is provisioned by Terraform — no custom domain or DNS setup required. Free tier: 100 emails/day. ACS is provisioned as part of the IaC (`infrastructure/modules/communication_service/`).

Three email types are implemented via `src/lib/email.ts`:
- `sendAssignmentNotification(recipients, templateTitle, dueDate, baseUrl)` — triggered fire-and-forget from `POST /api/admin/companies/[id]/assignments` when an assignment is created; individual assignments notify the specific user, company-wide assignments notify all company users filtered by `targetJobRoles`; both paths call `resolveEmailRecipients` so no-email workers route to their line manager
- `sendReminderNotification(recipients, templateTitle, dueDate, isOverdue, baseUrl)` — called by the daily cron job; subject says "Reminder:" or "Overdue:" depending on `isOverdue`
- Password reset — inline in `src/app/api/auth/forgot-password/route.ts`

`resolveEmailRecipients(users: UserData[])` in `src/lib/user-database.ts` — resolves a list of users to `{ email, name }[]` recipients, routing no-email users to their line manager and deduplicating by email (so one manager only gets one notification even if they manage multiple no-email workers in the same batch).

Automated reminders: `src/lib/reminders.ts` exports `isReminderDay(dueDate, today)` (fires on days -3, -1, 0, -7, -14, … relative to due date) and `getAssignmentsNeedingReminders(today)` which queries all due-dated assignments, applies job role filtering, resolves email recipients (including line manager routing for no-email workers), and returns outstanding users per assignment. `GET /api/cron/reminders` is the protected endpoint (`Authorization: Bearer {CRON_SECRET}`). `.github/workflows/reminders.yml` runs the endpoint daily at 08:00 UTC using the `prod` environment.

### Key Patterns
- Path alias `@/*` maps to `src/*`
- Tailwind CSS v4 for styling; Radix UI for accessible primitives; `cmdk` for the command palette; `@dnd-kit/core` + `@dnd-kit/sortable` for the form builder's drag-and-drop field reordering and palette drag-to-add
- `next.config.mjs` sets `output: 'standalone'` for Docker deployment
- **Design tokens**: `src/app/globals.css` is the single source of truth — a Tailwind v4 CSS-first `@theme` block mapping `--color-*` utilities onto OKLCH semantic tokens defined per theme. The palette is Supabase Studio's (values taken from `supabase/supabase`'s `packages/ui/build/css`): near-black canvas, hairline translucent borders, no shadows, 6px radii, `#3ECF8E` brand green. **Dark is the default** — dark values live on `:root` (so an unclassed document still paints dark) and `.light` overrides them; a blocking inline script in `src/app/layout.tsx` applies the stored class before first paint. Beyond the stock shadcn tokens there are `--success`/`--warning`/`--info` (+ `-foreground`), `--brand`/`--brand-tint`/`--brand-border`, `--border-strong`, `--field`, `--scrim` and `--sidebar*`. Prefer these over any hardcoded palette class; `bg-white` survives in exactly two places on purpose (the signature canvas, whose PNG is embedded in a PDF, and the QR code, which must stay scannable).
- **Typography**: Inter (`--font-inter`) + Source Code Pro (`--font-mono`) via `next/font/google`, wired into `@theme`'s `--font-sans`/`--font-mono`; `body` is `text-sm`, so unstyled text is 14px rather than 16px.
- **Navigation shell**: `src/components/app-shell.tsx` is the single global app shell — a sidebar whose behaviour is set by a **Sidebar control** menu pinned at its foot (`src/components/sidebar-control.tsx` — a radio menu of Expanded / Collapsed / Expand on hover, persisted in `localStorage` under `sidebar-mode`, default `hover`); plus a 48px top bar (breadcrumbs left; search / bell / theme toggle / avatar right). In `hover` mode the 56px rail widens to 224px on hover **and on `focus`**, overlaying the content; in `expanded` mode it is pinned open and takes up layout space instead of covering anything; in `collapsed` mode it never widens. The panel is also held open while the Sidebar control menu is on screen, since that menu is portalled outside the sidebar and moving into it would otherwise read as a mouse-leave. A spacer div holds the sidebar's layout width in the flex row (56px, or 224px when pinned expanded) while the `absolute` panel widens over the content. `src/components/app-sidebar.tsx` owns the nav model: `useNavGroups()` builds `NavGroup[]` (`{id, label, items}`) from the user's roles, where **every item carries its own icon** — groups only supply headings and are not themselves navigable. `findActiveItem` resolves the current page by *longest* href match (several items share a prefix, e.g. `/admin/completions` and `/admin/completions/outstanding`). `SidebarNav({ expanded, onNavigate })` is the single renderer, used by both the desktop panel and the mobile drawer (which passes `expanded` permanently, since there is no hover on touch). Labels and group headings are always in the DOM and fade via opacity, so nothing reflows vertically as the panel widens; collapsed rows get a right-side tooltip instead. Admin groups: Overview, Organisation, Documents, Compliance, Settings. Public/kiosk routes (`/auth`, `/signoff`, `/shared`, `/s/`) and signed-out users get a minimal top-bar-only chrome instead.
- **Command palette**: `src/components/command-palette.tsx` — ⌘K/Ctrl+K or the top-bar search button, built on `cmdk` via `src/components/ui/command.tsx`. Lists nav destinations from `useNavGroups()` (reusing each item's icon) plus, for Admin only, companies and templates fetched lazily on first open from the existing `GET /api/admin/companies` and `GET /api/admin/templates` (no new endpoints).
- **Page furniture**: `src/components/page-header.tsx` (`{title, description?, actions?, backHref?, backLabel?}` — the one page-title treatment, `text-xl font-medium`, used across `admin/**` and `customer/**`; `backHref`/`backLabel` render a small "← label" link above the title for pages nested under a list, e.g. a company or template detail page; `customer/welcome-header.tsx` wraps it), `src/components/empty-state.tsx` and `src/components/table-skeleton.tsx` (built on the new `ui/skeleton.tsx`) — used by every admin/customer table and list page in place of bespoke colspan "Loading…" rows and centred-paragraph empty states. `signoff/**` kiosk pages intentionally keep their own larger, high-contrast heading style rather than `PageHeader`, for legibility at a shared terminal.
- **DataTable**: `src/components/ui/data-table/data-table.tsx` — the one sortable table, backing every admin/customer list page (`admin/{companies,users,templates,assignments,activity,completions,completions/[companyId],completions/[companyId]/[templateId],completions/history,completions/outstanding,companies/[id]}`, `customer/{completions,admin/completions,admin/templates}`; the documents browser at `src/app/documents/data-table.tsx` is unrelated — it needs row selection/bulk-delete/drag/mobile-card layout TanStack Table directly gives it, so it was left as its own component). Built on TanStack Table v9's feature API (`useTable`/`tableFeatures`, not the v8 `useReactTable`); `src/components/ui/data-table/table-features.ts` declares just the sorting feature (`dataTableFeatures`) and module-augments `ColumnMeta` with an `align` field (`'left' | 'right' | 'center'`, applied to both the header and every cell in that column — e.g. an actions column). Takes `columns`/`data` plus `isLoading` (renders `TableSkeleton`), `emptyTitle`/`emptyDescription` (renders `EmptyState`), `getRowId`, `rowClassName`, and either uncontrolled or controlled (`sorting`/`onSortingChange`) sort state — controlled is used where a page also needs the current sort order for something else, e.g. CSV/XLSX export on `admin/completions/outstanding`. `wrapperClassName` (default `'rounded-md border'`) can be cleared to `''` when nesting a `DataTable` inside a container that already draws its own border — used by the collapsible per-category/per-company groups on `admin/templates`, `admin/users` and `admin/companies/[id]`. `src/components/ui/data-table/sort-utils.ts` exports `nullableDateSortValue` (null sorts as "latest" — last ascending, first descending) for due-date-style columns via `accessorFn`.
- **Breadcrumbs**: `src/components/breadcrumbs.tsx`, rendered in `AppShell`'s top bar, shows a trail on nested pages only (hidden when there'd be fewer than two crumbs — top-level pages rely on the sidebar's active state instead). It derives static segment labels from a `ROUTE_LABELS` map and resolves dynamic id segments (company/template/completion names) via a registry populated by the pages themselves through `useBreadcrumbLabel(path, label)` (`src/components/providers/breadcrumb-provider.tsx`, `BreadcrumbProvider` wraps `AppShell` in the root layout) — e.g. `admin/companies/[id]/page.tsx` calls `useBreadcrumbLabel(`/admin/companies/${id}`, company?.name)` once the company loads. Trailing action segments (`view`, `complete`) fold into the entity crumb before them rather than appearing as their own crumb. `/documents` is excluded — the file browser has its own in-page folder breadcrumb (`document-breadcrumb.tsx`).
- **Account menu**: `src/components/user-menu.tsx` — an avatar (initials) dropdown in the top bar grouping Profile and Sign Out.
- **Notification bell**: `src/components/notification-bell.tsx` — top bar bell showing a badge of overdue completions plus templates due for review (admin: `templatesDueForReview` from the same stats call; customer admin: `GET /api/customer/admin/templates/review-due`, which also backs `ReviewDueCard` on `/customer/admin/completions`), polled every 5 minutes. Visible only to Admin (via `/api/admin/dashboard/stats`'s `overdue` KPI) and Customer Admin (via `/api/customer/admin/completions`'s `isOverdue` groups) — the roles responsible for chasing outstanding sign-offs; links to the relevant outstanding/overdue view. Not shown to individual customer users or tenant staff.
- **Welcome header**: `src/components/customer/welcome-header.tsx` — a one-line "Welcome back, {first name}" + status subtitle used on the customer landing pages (`/customer/documents`, `/customer/admin/completions`) for orientation; subtitle reflects pending/outstanding counts once loaded.
- **Landing route**: `src/app/page.tsx` (`/`) is a server-side role redirect, not a page — admin → `/admin` (dashboard), customer admin → `/customer/admin/completions`, customer user → `/customer/documents`, tenant staff → `/documents`, signed-out → `/auth/signin`. The relevant dashboard/list is each role's home; there is no standalone home page.
- `src/proxy.ts` is the Next.js 16 proxy (formerly middleware) — guards `/documents` and `/scan` routes with auth; named `proxy` not `middleware`. (Document scanning at `/scan` is built but currently unlinked from navigation — it will return later.)
- All activity is logged to Azure Table Storage for auditing
